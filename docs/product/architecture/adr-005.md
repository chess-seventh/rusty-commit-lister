# ADR-005: Clipboard via OSC 52 terminal escape (supersedes ADR-004)

**Status**: Accepted

**Date**: 2026-07-26

**Decider**: Vulcan — approved by franci

---

## Context

ADR-004 chose the `arboard` crate for clipboard copy. The primary environment has since moved to
**Wayland/Hyprland**, where `arboard` fell back to the X11 (XWayland) backend and copies timed out:

> `WARN arboard::platform::linux::x11: Could not hand the clipboard contents over to the clipboard
> manager. The request timed out.`

The timeout also blocked the event loop, and the warning was written to the terminal while the TUI
owned the alternate screen — corrupting the display.

Enabling arboard's native Wayland backend (`features = ["wayland-data-control"]`) fixed the copy but
pulled in a large tree:

- ~15 crates including `wayland-*`, `wl-clipboard-rs`, and a build-time `quick-xml`.
- `quick-xml` carried `RUSTSEC-2026-0194` and `RUSTSEC-2026-0195` (both build-time XML parsing of
  trusted wayland protocol files — not exploitable here, but they still fail `cargo deny` in CI).
- Extra licenses that would need an explicit `deny.toml` allow-list.

---

## Decision

**Copy via the OSC 52 terminal escape sequence** (`src/adapters/osc52_clipboard.rs`): the app asks
the terminal emulator itself to set the clipboard by writing `ESC ] 52 ; c ; <base64> BEL` to stdout.

Rationale:

- Works on Wayland, X11, **SSH**, and tmux (`set-clipboard on`) — the terminal performs the copy, so
  no system clipboard library or display server is required.
- Zero dependencies: base64 is a small in-crate pure function, so `arboard` and the entire wayland
  tree are removed, along with the `cargo deny` friction.
- Copy-only is sufficient — the `Ctrl-Y/E/P/U` actions only ever write; the tool never reads the
  clipboard back.
- The `ClipboardPort` trait is unchanged, so only the adapter file differs; `probe()` always
  succeeds (OSC 52 needs no backend), and an unsupported terminal simply no-ops the copy.

Logs are also discarded while the TUI is active so no warning can bleed onto the alternate screen;
`RUST_LOG` is still honored for non-interactive runs.

---

## Alternatives Considered

- **arboard + `wayland-data-control`** (rejected): works natively on Wayland with X11 fallback, but
  adds the heavy dependency tree and advisories above, needs a `deny.toml`, and still cannot copy
  over plain SSH.
- **Shell out to `wl-copy` / `xclip`** (rejected): requires those binaries to be installed and a
  running compositor; fails over SSH; duplicates platform detection.

---

## Consequences

- Positive: one dependency-free code path covers Wayland, X11, SSH, and tmux; smaller `Cargo.lock`;
  no security-advisory or license exceptions to maintain.
- Negative: relies on terminal OSC 52 support (foot, kitty, wezterm, alacritty, and tmux with
  `set-clipboard on` all support it). Reading the clipboard is not supported, which the tool does
  not need.
- ADR-004 is superseded; its analysis is retained for history.
